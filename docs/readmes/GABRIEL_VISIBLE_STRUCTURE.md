# Local visible-page structure drafts

The explicit **Preview visible structure** and **Share reviewed structure** extension controls preserve visible headings, ordinary table headers/cells and unambiguous definition-list label/value pairs on the currently approved tab. No vendor name, Gabriel page marker or generated-console JSON is required. This is structural observation, not arbitrary-dashboard incident interpretation, console identity authentication or a qualified detection engine.

The structure preview is separate from ordinary text sharing and scheduled review. Inspect its exact JSON before approving it. Sensitive content can be removed by deleting whole heading, table or label/value blocks; retained blocks must still match a fresh visible read. Changing a field value, adding a block, moving cells or modifying the approved scope label is rejected. Cancel sharing or select a narrower view when a sensitive block cannot safely be shared. Raw previews are not retained in extension storage. Stop, Pause, navigation, tab changes and popup visibility loss invalidate preview approval.

The capture remains limited to the selected document's visible top frame. Forms, editable controls, hidden, covered, clipped, offscreen and frame content stay excluded. Reference IDs are generated local positions such as `h1`, `t1/h3`, `t1/r2/c3` and `p1/value`; page-supplied selectors and attribute IDs are not trusted references. Missing middle headers/cells retain missing column positions rather than shifting visible values. These are recorded DOM positions, not an assertion that CSS presented the same visual order. Multiple/later/footer header sections, merged cells and nested tables are unsupported and stop the capture. Unsupported definition-list layouts supply no inferred pairs.

The maximum capture is 64 KiB UTF-8, with twelve heading positions, eight tables, sixteen columns, thirty-two visible rows per table and thirty-two explicit label/value positions. Individual fields are limited to 1,024 characters; the non-secret operator-declared scope label is limited to sixty-four. Excess or unsupported capture layouts fail rather than silently presenting truncated structure as complete. Browser visibility claims and that literal scope-label match do not authenticate the dashboard account or source.

Sharing reuses the existing HTTPS observation envelope, encrypted local evidence store and durable capture receipt. The new local `structure-review` operation accepts only the current operator's latest completed capture for the exact case/lease/context. It verifies stored source bytes, checksum, custody, receipt, freshness and post-navigation capture state, then rechecks after storing the draft. A changed capture, Stop, expiry, revoked authority or source drift prevents a successful processing response. An uncertain capture/review outcome is not automatically retried.

Every stored draft is permanently labelled **unreviewed historical structure**, including one retained when a later source recheck fails. It is never a publication receipt or a current source-health result. Its immutable contents retain the source observation/evidence IDs, source checksum, original client and receipt times, immutable capture-request digest and receipt hash. Visible-row counts remain counts of captured structure; event counts and field meanings remain unknown. Documentation, aggregate totals, historical records and event rows can look alike.

Open the draft evidence record in the authenticated workbench, then explicitly choose **View evidence content**. The structural view recomputes the transformation from the actual original browser observation and receipt, checking its case, source parent, checksum and deterministic draft identity. Matching an arbitrary uploaded JSON label alone is insufficient. The existing owner/admin/analyst content permission applies; a viewer receives metadata only. Historical drafts can still be read after Stop under current content permissions, without resurrecting the original lease. Their quoted text is escaped and rendered as untrusted evidence.

This feature makes zero model calls and admits no incident facts, learned memory, provider routes, navigation capabilities or external actions. The existing Hermes partial-capture guard remains intact. Reviewed semantic mapping, qualified interpretation, finite background Hermes orchestration, independently evaluated model quality, real-console acceptance and actual native-device/operational acceptance remain separate work.

The focused Docker workflow exercises contract rejection, encrypted source custody, latest-source and navigation invalidation, late changes during draft storage, same-label/digest spoof rejection and content-role isolation. The packaged Chrome/Brave lab additionally exercises three differently branded/reordered unmarked generated pages, source-position privacy exclusions, actual popup consent, HTTPS capture/review and an authenticated historical draft content view. It retains a generated-data screenshot and source/draft checksum metadata for each browser. Until those runs pass, these are implemented checks awaiting execution; generated-page results do not establish production-console or native-OS acceptance.
