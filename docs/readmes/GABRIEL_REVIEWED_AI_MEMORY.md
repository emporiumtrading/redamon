# Reviewed historical context for specialist AI

Operational specialists can request `review_memory` during their bounded reasoning loop. The analyst's AI-export consent includes eligible reviewed typed historical references. The twelve role configurations and qualification fingerprints include the tool, its usage skill and the historical-context implementation. Wiring the feature does not qualify any model or admit a configuration for production.

Only explicitly approved `fact` memory containing a valid `specialist-facts-v1` document is considered. The memory root and each referenced source must pass current evidence integrity, case/organization scope and source-binding checks. Plain text, browser passage summaries, preferences, restricted-classification memory, unrelated identifiers, role-irrelevant facts and facts dated after the current input snapshot are excluded. They are never interpreted as instructions or silently converted into facts for the model.

The local reader admits at most four reviewed records and six relevant historical assertions. It reuses current packet aliases for matching supplied entity UUIDs; matching an identifier does not establish verified identity. The model receives only closed-schema fields, source-reported event times and aliases. Actual memory, case, record, entity and evidence identifiers remain in the encrypted local manifest. Free-text memory never crosses the provider boundary through this tool.

Current observations use `o` references; historical assertions use separate `h` references. Historical references are not current events, current authorization, an independently verified baseline or independent corroboration. Disagreement and time differences require review. Current urgent-exposure guards remain in force. The Hermes report receives a count of historical-reference claims instead of relabeling those claims as current observations or guessing their contents.

Selected memory records are revalidated before further dispatch and after provider I/O. Forget, reset, correction, expiry, source loss, source corruption or authority loss prevents reuse; a changing context does not authorize another paid send for an existing claim. Existing encrypted evidence remains under retention and legal-hold policy. A replay whose original context is no longer eligible must be reviewed or restarted as a separately identified investigation, rather than rewriting the original input.

Performance-test cases disable this tool's historical retrieval, including organization references. They also retain the database/service prohibition on learning proposals. TryHackMe remains a future performance exercise after production readiness and access; its observations and answer keys cannot become these references. This context mechanism performs no fine-tuning or model-weight update.

Generated Docker integration checks exercise each role, identifier minimization, free-text/restricted/unrelated exclusions, historical lineage, pre-dispatch forgetting/reset/correction/expiry, and performance-case exclusion. Real-provider suitability, poisoning effectiveness and operational usefulness still need independent evaluation before production admission.
