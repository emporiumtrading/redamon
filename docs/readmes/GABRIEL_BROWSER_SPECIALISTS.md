## Transactions, cancellation and recovery

The private gateway uses the existing exact extension origin, bearer pairing, original human session, case/task, account/document, sharing approval, generated adapter grant and lease checks. Prepared capture or navigation outcomes block review. There is no public provider credential or new network dispatch.

Facts are acquired idempotently under an observation/version-derived ingestion ID. All twelve specialist results and the suite receipt publish in one bounded local database transaction. Saved per-role request IDs and result digests bind replay. An audit or receipt failure rolls back the entire suite; an already acquired encrypted facts artifact may remain for inspection. Retry reuses it. Actual source bytes and current authority are checked again on replay. The 128-specialist-run case quota rejects a new suite before partial publication. A ten-second wall-clock budget is checked between local operations and before publication; it cannot interrupt an individual in-progress filesystem or database call.

Stop is terminal for the delegated browser session. A Stop already applied before the suite writer prevents new specialist results. The short suite transaction holds the organization lock; an in-progress local transaction can finish before a concurrent Stop is recorded. The gateway also serializes its requests. This protocol must not wrap long model calls or external effects. A client timeout or worker suspension reports an unconfirmed outcome and never authorizes automatic replay, recapture or new navigation.

Schema 26 adds the append-only suite receipt and extension-version compatibility while retaining 0.1.0 and 0.2.0 leases.
