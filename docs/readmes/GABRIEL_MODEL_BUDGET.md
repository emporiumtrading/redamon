# Durable model cost control

The local budget service reserves costs in PostgreSQL before a model call could be claimed. Schema 16 adds append-only policies, price attestations, investigations, reservations, one-time claims, settlements and Stop records. Each operation uses verified human membership and the existing tenant transaction lock; browser/worker tokens cannot become budget administrators. Mutations and their audit event commit together. No provider credential, prompt, response, evidence body or URL is stored in these tables.

Defaults are $18 monthly dispatch allowance within the owner's $20 envelope, $0.50/day, $0.05/investigation, 15-minute investigation slices, at most two unresolved reservations per tenant and six reservations per investigation. Each retry/fallback is a new reservation with a new request ID and counts toward the same limits. Transport-specific retry backoff and the maximum-two-retry rule remain coordinator/transport obligations, not features delivered by this local ledger. Limits can be lowered or paused through the authenticated administrator CLI; this increment cannot raise them above these ceilings.

Amounts are integer micro-USD (1 USD = 1,000,000 units). Price attestations specify input/output micro-USD per million tokens; reservations round upward, including a one-microdollar floor for nominally free routes. Input and total output/reasoning ceilings are 8,000 and 1,500 tokens. Only the selected OpenRouter Flash Lite/Flash and NVIDIA Nemotron candidate identifiers are admitted for local accounting. A price quote is an administrator attestation lasting at most one hour, not verification of current provider pricing, confidentiality or model quality. Changed price/configuration means a new quote; a request retry with a changed quote/input digest/token ceiling is rejected.

Stop releases only never-claimed reservations. Once claimed, expiry, timeout, restart, policy pause, creator revocation or Stop cannot establish that nothing was charged. Unsettled reservations retain their cost and slot across UTC day/month boundaries. Late operator settlement counts conservatively against both the originating and reconciliation buckets. This can temporarily reduce throughput; it avoids assuming an uncertain charge disappeared. Settlements require current owner/admin authority, a unique receipt digest and explicit actual cost. Excess actual cost is recorded and can block later work; a ledger cannot retroactively prevent a provider overcharge. Refunds, pricing updates and multi-currency accounting are not admitted here.

The settlement attestation is operator-supplied, not authenticated provider billing. Dedicated provider keys/account caps are needed before actual transport; tenants sharing a provider key need one shared account-level spending authority, not independent tenant ceilings over the same balance. Concurrent other applications using that key are outside this tenant ledger. Do not claim this service alone guarantees the entire provider account stays under $20. Headroom is not proof that every fee or exchange movement is covered.

## Operator interface

The identity image includes `python -m gabriel.identity.budget_cli --token-file /run/operator/session status` and subcommands `configure`, `quote`, `begin`, `reserve`, `claim`, `settle`, `stop`. Use the existing restricted application DSN through `GABRIEL_IDENTITY_DSN_FILE` and a current protected human-session file. Do not put keys or raw evidence in CLI arguments. Amount/rate arguments explicitly use micro-USD units.

`quote` accepts provider, model, configuration digest, input/output rates and TTL; `begin` binds an open case and idempotent request ID; `reserve` binds investigation, idempotent request ID, quote and input digest. `claim` returns `new_claim` exactly once; replay reports the historical claim without creating a second one. `settle` records actual micro-USD and receipt digest. `stop` stops the investigation and releases unclaimed work. Status reports current limits, UTC buckets and held slots. The API and CLI always disclose that transport and model admission are disabled. These are working local accounting operations, not a pretend provider dispatch.

No HTTP/browser route, provider transport or live AI engine is enabled by this increment. Future transport must bind the exact payload/configuration to these reservations, enforce model/privacy admission, use a restricted dispatcher credential, verify genuine usage provenance, reconcile uncertain effects and never re-send a prior claim. The human-only claim interface must not be reused as an unrestricted remote worker credential. UI spending controls, live-price ingestion, the coordinator, network worker and model-quality acceptance remain separate deliverables.
