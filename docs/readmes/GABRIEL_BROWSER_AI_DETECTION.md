# Browser AI detection application phase

The browser-to-model application bridge is implemented for bounded candidate-signal triage. Production model activation remains disabled: the exact configuration is not admitted, no live trial has run for this new projection, and independent qualification is pending. This is not a claim of general console understanding or qualified live threat detection.

## What the bridge does

For a separately approved scheduled capture, the backend verifies the original operator/session, tab/document, lease, task, case, capture receipt and ciphertext. The local projector recognizes authentication, malware, control-tampering and network-alert candidate passages. The provider receives only category names, matched-passage counts and server collection time, with explicit gaps and opaque observation references. Matched passages are not event counts; collection time is not event time. No actor, asset, impact, source authenticity or independent corroboration is invented.

Raw page text, names, URLs, local evidence IDs, secrets and reviewed-memory content stay local. Unsupported or negated/no-signal content abstains locally without a provider call. Long or excess matches disclose omissions. This restricted projection cannot interpret every page, image or vendor-specific event.

The existing worker applies exact configuration admission, checked database-vault credentials, route/privacy/credit preflight, budget reservation, a durable single dispatch claim and strict response validation. Results are encrypted as **Unreviewed generated model answer** evidence with local source lineage. A model disposition is not a confirmed incident. No tools, remediation or external response actions are granted.

Stop can revoke the browser lease while provider I/O is pending. An uncertain claimed call never automatically resends. Completed receipts replay as historical answers. AI waits are bounded to 40 seconds with current-document and heartbeat checks around dispatch; an unresolved result leaves the cursor for inspection.

Each AI plan freezes only its original capture and normalized input. Unrelated additions to the same case do not invalidate an in-flight review. The existing two-slot concurrency limit remains enforced. A capacity deferral resumes only when the server explicitly confirms that no reservation or dispatch occurred; it does not recapture the page. Unknown dispatch outcomes are never automatically repeated.

Completed calls count their full reserved ceiling as spending, rather than claiming that an operator verified a provider bill. Migration 28 requires a completed answer receipt, the original claimant and exactly that reserved amount before clearing the uncertainty slot. Unknown calls retain their reservation and slot. Existing daily/monthly/investigation limits still apply.

## Readiness and operator activation

The rebuilt image exposes readiness without credentials or a network:

```bash
docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges --entrypoint python IMAGE_ID -m gabriel.identity.gateway_cli ai-readiness --ai-model openai/gpt-oss-120b
```

This prints the exact configuration digest and admission state. The current admission state is false. Adding a key or checking the companion's checkbox cannot override it.

After a reviewed release admits that exact configuration, the existing private gateway preparation command can include `--ai-model openai/gpt-oss-120b`, along with `--approve-observation-sharing`, `--monitor-seconds 300` and the existing case/task/context/origin/endpoint arguments. Preparation requires an owner/admin and refuses an unadmitted model. The trusted gateway requires its evidence and provider keyrings; credentials must have completed the existing provider onboarding checks. In the companion, scheduled sharing and the separate minimized-signal AI checkbox must both be approved. The popup reports the AI outcome; the case evidence table links the unreviewed answer.

The default private Docker installation still has an internal network and no provider egress. The browser gateway is a separate operator-run service; its provider-capable runtime/network, TLS endpoint and secret mounts need explicit deployment and acceptance. This increment does not silently open the private workbench's network. Rebuilding the image by itself does not start a gateway or enable live inference.
