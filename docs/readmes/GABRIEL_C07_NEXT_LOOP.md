This document defines the next implementation sequence, not implemented specialist capability.

1. Implement versioned specialist input/output contracts for the twelve PRD roles, activating none merely because a name is registered. The first five candidates are telemetry health, alert triage, incident scoping, threat intelligence and threat hunting. Inputs must resolve current tenant/case/evidence access through the existing service. Outputs must cite admitted evidence, distinguish observations from hypotheses, retain contradictory/benign alternatives, permit abstention, and identify provider/model/prompt/playbook/tool versions and actual measured costs. Repeating one source or asking multiple models does not create independent corroboration. No confidence field can certify universal attacker absence or certainty 1.0.
2. Implement governed baseline/memory storage before automated reuse. Keep proposed facts distinct from analyst-validated environment facts and preferences. Require provenance, reviewer, scope, sensitivity, observation/validation dates and expiry. Implement immutable correction/supersession, explicit invalidation and current-authority rechecks; facts never grant permissions. Retrieval must exclude expired, superseded, deleted, wrong-tenant and revoked-source material. Define and implement the retention-hold/deletion/reset boundary before admitting memory reuse. An answered question, dismissed alert or repeated attacker behavior is not a validated benign fact.
3. Implement a bounded coordinator with durable budgets, cancellation, disagreement/duplicate handling and audit. Its tool allowlist must use actual accepted capabilities; browser navigation/search and external response remain unavailable until their own adapters and dispatch controls are accepted. No arbitrary URL, query, script or executable tool can come from an untrusted page, memory record or model output.
4. Admit actual NVIDIA/OpenRouter or other provider dispatch only after the model-policy decisions are supplied through the approved configuration process: exact routes/models, permitted data classes, privacy/retention/residency and spend limits. Provider credentials stay in the encrypted backend vault. Fallback must preserve policy; route failure cannot trigger broader data egress. Do not return fabricated model results or pretend a disabled dispatch is a working integration.
5. Evaluate real enabled roles on a lawfully usable, analyst-adjudicated held-out corpus, including benign alternatives, active-attack examples, missing/contradictory evidence, stale clocks, partial browser coverage, poisoning, prompt injection and outages. Generated fixtures test contracts and failure boundaries; they do not establish expert detection accuracy. Measure false positives/negatives, abstention/escalation, evidence support, analyst workload, latency and cost against declared thresholds.

Each implementation increment must pin its source/schema and requirement IDs, define acceptance and rollback first, use real persistence/tools, run the matching-image per-file gate, repair observed failures without relaxing controls, and record artifacts. Re-run affected recovery and native-browser paths when their behavior changes. Keep security effectiveness, uncertainty, operational exposure and compliance status distinct.

Live model, expert-quality and real-console gates depend on the actual inputs in [the decision register](GABRIEL_ACCEPTANCE_DECISIONS.md). Independent contract/memory/coordinator implementation can proceed without inventing these decisions. Human staging UAT, regression before release and human post-release UAT/regression remain mandatory. No production release, supported integration or complete PRD requirement is accepted by this plan.
